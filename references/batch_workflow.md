# 批量流程：多篇论文同时做

## 分工

| 角色 | 做什么 | 权限 |
|---|---|---|
| 执行者（子代理） | 读 3–4 篇全文，写对应的数据文件，跑检查脚本到通过 | 只写自己那几篇的 `papers/<id>.js`；PDF 只读 |
| 汇总者（主会话） | 统一生成、看图、修模板、抽查数字、汇报 | 可改模板和检查脚本 |
| 用户 / 导师 | 确认格式样板，判断相关性与结论是否可信 | 最终裁决 |

## 步骤

1. **样板**：先做 1–2 页（一篇理论、一篇实证），请导师确认格式，再批量做。
2. **统一规范**：所有执行者用同一份说明（见下方模板）、同一套字段和两页范例。
3. **分组并行**：每组不超过 4 篇。长篇工作论文（70–125 页）单独成组，只读模型部分和命题，跳过证明。
4. **验收**：执行者交回时，检查脚本必须 OK，并报告"没找到"和"没把握"的地方。
5. **汇总检查**：生成整份 PPT → 逐页看图 → 共性问题改模板，个别问题改数据文件 → 再看一遍改过的页。
6. **停止条件**：同一页改两轮还溢出，就删内容（删次要变量、合并要点），不再缩小字号。

## 中断与恢复

- 子代理因额度或网络中断时，已写好的文件会保留。恢复后让同一个执行者从中断处继续，不要重新分派，避免同一篇被写两遍。
- 恢复前先列出已存在的数据文件，并跑一遍检查脚本，确认哪些写完了、哪些没通过。

## 给执行者的说明模板

```text
你负责为以下论文各写一个阅读总结数据文件。准确比速度重要，读者是导师。

项目背景：<一两句研究问题>
导师要求：<粘贴 reading_questions.md 中对应类型的问题>
写作规范：<粘贴 writing_rules.md 的要点>
格式：先完整阅读 assets/examples/papers/ 下的两个范例和 references/field_spec.md。

做法：
1. 用 pypdf 提取全文到 <临时目录>，读摘要、引言、模型或数据、主要结果、结论。
2. 写 <papersDir>/<文件名>.js。
3. 运行 node scripts/check_paper.js <文件>，改到 OK。
4. 只改你自己的文件。

你的论文：
| id | 文件名 | 类型提示 | PDF 路径 |

交回（简短）：每篇的文件名、类型、一句话主要结果、检查是否通过、是否加图（依据什么）、没找到或没把握的地方。
```
